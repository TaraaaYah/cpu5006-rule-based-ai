# Paper guide – CPU5006 Assessment 1 (Car Evaluation, rule-based AI)

This is a blueprint and evidence pack, **not** the paper. The marking criteria reward *your* critical analysis and
penalise unadapted AI-generated text, so the writing needs to be yours. Everything below is reproducible with
`python run_experiments.py` (about 1 minute; identical results on repeated runs).

## 1. Suggested research question
> Can an automatically induced rule list (CN2) recover the decision logic behind car acceptability better than a
> hand-built, hierarchy-based expert system, and how many labelled examples does induction need before it overtakes
> hand-written knowledge?

Useful facts about the dataset (cite `car.names`): 1,728 cars covering the *complete* attribute space (4x4x4x3x3x3, each
combination once), no missing values, no duplicates. Classes: unacc 70%, acc 22%, good 4%, vgood 4%. The labels were
generated by a hierarchical rule model (DEX; Bohanec and Rajkovic, 1988), with the hierarchy removed in this version.

## 2. The two algorithms
1. **Hierarchical expert system** – forward chaining through three layers: PRICE (buying, maint), COMFORT (persons, doors,
   lug_boot) and TECH (comfort, safety), then an ordered final rule list. Not trained on data (18 rules).
2. **CN2** – multi-class ordered rule-list induction (beam search, Laplace accuracy, chi-squared significance test,
   ordinal selectors such as `safety >= med`). Defaults (beam 5, max length 4, min coverage 5) were fixed before the grid search.

## 3. Headline results (10 repeats x 5-fold stratified CV)

| Model | Accuracy | Macro-F1 | Kappa | Ordinal MAE | Recall acc / good / vgood | Rules |
|---|---|---|---|---|---|---|
| Majority class | 0.700 | 0.206 | 0.000 | 0.415 | 0 / 0 / 0 | 1 |
| 1R | 0.700 | 0.206 | 0.000 | 0.415 | 0 / 0 / 0 | 4 |
| Expert system | 0.793 | 0.421 | 0.459 | 0.240 | 0.41 / 0.09 / 0.09 | 18 |
| **CN2** | **0.967** | **0.919** | **0.927** | **0.039** | **0.95 / 0.84 / 0.87** | 38.5 |

CN2 vs expert system (Nadeau-Bengio corrected t-test, `results/significance.csv`): accuracy +0.174, macro-F1 +0.498,
kappa +0.468 (all t > 20, p < 0.001). Ordinal MAE (average distance on the unacc < acc < good < vgood scale) falls from 0.24 to 0.04.

**Learning curve** (`results/learning_curve.csv`, Fig. 3): CN2 macro-F1 is 0.41 with about 70 labelled cars, 0.51 with about
140, 0.66 with about 280, 0.82 with about 550 and 0.93 with about 1,380. It overtakes the (flat, 0.43) expert system at
roughly 70-140 labelled cars.

**Ablation** (Fig. 4): ordinal selectors help, especially when min coverage is high (macro-F1 0.85 vs 0.78 at min coverage 20)
and slightly at the defaults (0.918 vs 0.896).

## 4. Things worth discussing (this is where the marks are)
1. **Accuracy hides the real story.** The majority class scores 0.70 accuracy but macro-F1 0.21. The expert system's
   0.79 accuracy comes almost entirely from "unacc", with recall of only 0.09 on good and vgood (Fig. 1b, Fig. 2).
2. **1R equals the majority class.** No single attribute reduces training error, so 1R predicts "unacc" every time. The
   concept depends on interactions between attributes, which is exactly what single-attribute rules cannot capture.
3. **CN2 rediscovers the knock-out logic.** Its first two rules are `persons == 2 -> unacc` and `safety == low -> unacc`
   (`results/induced_rules_cn2.txt`). Compare with how the expert system encodes the same idea via the TECH concept.
4. **Why the expert system fails (`results/expert_error_examples.csv`).** 216 of 384 "acc" cars were rejected as unacc,
   138 by the "tech poor -> unacc" knock-out and 78 by "price expensive -> unacc": my generic thresholds are too strict. Good
   discussion of knowledge-acquisition difficulty (the "knowledge acquisition bottleneck").
5. **Interpretability trade-off.** The expert system is small, layered and explains each decision in concepts a buyer
   understands. CN2 is accurate but flat: 38.5 rules on average, some late rules are tiny fragments (e.g. rule 29 covers
   5 cars), and rule order matters. Accuracy and interpretability pull in opposite directions here.
6. **Data efficiency.** Hand-written rules need no data but plateau; induced rules need data but keep improving. The
   crossover at about 70-140 cars is a practical finding about when to invest in elicitation versus labelling.

## 5. Limitations you should state honestly
- **The expert rules were written by an AI assistant, once, without tuning, but not blind.** I had already seen the class
  counts and the `safety`/`persons` crosstabs, which show that `safety = low` and `persons = 2` are always unacceptable.
  So the expert system is *informed by the data* at that level, and arguably a weak, generic expert. A stronger design:
  write your own rules from the hierarchy in `car.names`, justify each one, and optionally refine them on a development
  split that is excluded from the final evaluation. Tell the marker how you did it.
- **A "perfect" expert exists.** The labels come from the published DEX model, so a system encoding that model would
  score about 100%. The expert system here is therefore a model of *imperfect* hand-written knowledge, not an upper bound.
- **No noise.** The data is deterministic and complete, so every error is a generalisation error from partial data.
  This limits external validity (real data is noisy); a label-noise experiment is a natural extension.
- The CN2 settings grid used the same CV as the headline numbers, so the best grid cell is slightly optimistic. The
  defaults were fixed in advance.
- CV standard deviations for the expert system are about 0 because it is deterministic; they reflect partitioning, not
  sampling uncertainty. That is why the corrected t-test is used.
- The ordinal metrics assume the class order unacc < acc < good < vgood, which is an assumption.
